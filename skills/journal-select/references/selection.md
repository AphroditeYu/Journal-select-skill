# 匹配与排序

## 先过滤，再比较

硬条件来自用户而非 Skill 预设：语言、文章类型、必须的数据库类别、单位认可、预算、OA/资助要求等。时间硬截止通常只能判断已知冲突与风险，不能把历史中位数作为时限保证。

若所有候选不符合，明确说明没有合格推荐，列出可讨论的约束调整；不得偷偷放宽条件或将最不差者称为合格。

## 默认比较维度

| 维度 | 推荐依据 |
|---|---|
| 问题和读者匹配 | scope 与近期论文是否面向同类问题及读者 |
| 方法与文章类型 | 是否接收该类型；近期相似方法的使用方式 |
| 贡献程度 | 近期文章体现的证据深度和贡献要求；区分观察与推断 |
| 研究透明度要求 | 数据、代码、伦理、注册及报告清单是否能满足 |
| 时间与成本 | 预算是否覆盖确定费用；周期证据及不确定性 |
| 声誉与稳定性 | 官方收录状态、预警、同行评议和费用透明度 |

对于深入推荐的期刊，尽可能提供 2–3 篇近期且相关的真实论文作为匹配依据，注明题目、年份与 DOI/链接，以及“哪里相似、哪里不同”。冷门领域、篇数少或无法访问时说明限制，不凑数、不虚构文献。

每项使用高/中/低/未知并解释。高匹配不能抵消硬条件不符合。不要按出版商品牌整体判好坏，也不要单凭 OA、发文量或审稿快认定掠夺性。

## 用户要求量化时

先给出可调整的权重，说明这是决策辅助而非经校准的预测模型。未知项不得默认为零或平均值，也不得对缺失维度自动重新归一化后跨刊排名。优先保留定性判断；必须计算时用清楚标注的区间或暂不计算总分，并并列呈现证据完整性。

## 投稿顺序与调整建议

顺序取决于用户对学术传播、认定、时间、费用的优先级。挑战目标不意味着值得无条件先投；期限紧时可优先匹配度较高、时间证据较清楚的候选。

每本给出一个主要推荐理由、一个主要拒稿风险及具体的准备动作。例如澄清方法适用条件、缩短超长稿件、准备数据可用性声明。不要建议更改真实结果或人为补充目标期刊引用。

只给建议顺序，不安排同时投递。被拒后用实际编辑意见更新论文画像和候选判断。
